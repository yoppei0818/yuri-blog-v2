# フェーズ 4: 記事・読了本の詳細ページ計画

## 概要

Nuxt Content の `articles` / `books` collection を使い、技術記事と読了本の詳細ページを作ります。
<br>一覧で見つけたコンテンツを読みやすく表示できることを優先し、Markdown 本文、メタ情報、前後の導線を共通のブログレイアウトにまとめます。

技術記事は本文を主役にし、公開日、更新日、タグ、目次、関連記事を表示します。
読了本は Phase 2 で本文付き Markdown として管理する方針にしたため、一覧のみにはせず、読書メモを読める詳細ページを作ります。

Phase 2 のコンテンツ設計を優先し、Phase 4 では `readingTime` / `rating` / `category` を追加しません。

## URL とファイル構成

```txt
app/
  pages/
    articles/
      [...slug].vue
    books/
      [...slug].vue

  components/
    ContentProse.vue
    ArticleMeta.vue
    ArticleRelatedList.vue

content/
  articles/
    2026/
      nuxt-content-blog.md
  books/
    2026/
      document-writing.md
```

想定 URL:

- 技術記事: `/articles/2026/nuxt-content-blog`
- 読了本: `/books/2026/document-writing`

補足:

- Nuxt Content が生成する `path` を詳細ページの URL として利用する
- 年別ディレクトリを URL に含め、同じ slug を別の年でも利用できるようにする
- トップページの記事カードと読了本カード全体を、それぞれの `path` へのリンクにする
- 記事一覧ページと読了本一覧ページは Phase 5 で作る

## 共通レイアウト

```txt
詳細ページ
  ヘッダー

  コンテンツヘッダー
    種別
    タイトル
    公開日
    更新日
    タグ

  本文エリア
    Markdown 本文
    目次

  フッター導線
    一覧へ戻る
    関連記事

  サイトフッター
```

- `SiteHeader` / `SiteFooter` はトップページと同じものを使う
- PC では本文 + 目次の 2 カラム、モバイルでは本文のみの 1 カラムにする
- 本文幅は読みやすさを優先し、トップページのカードグリッドより狭くする
- 目次は見出しがある場合だけ表示し、モバイルでは本文上部の折りたたみ表示を検討する
- 記事・読了本の詳細から各一覧へ戻る導線を表示する
- 存在しないコンテンツ、または `published: false` のコンテンツは 404 として扱う

## 技術記事詳細

技術記事では次の情報を表示します。

- `title`
- `description`
- `publishDate`
- `updated`
- `tags`
- `thumbnail`
- Markdown 本文

表示方針:

- タイトルの上または下に公開日と更新日を表示する
- `updated` がない場合や `publishDate` と同じ場合は更新日を省略する
- タグは記事一覧と同じ配色の `UBadge` で表示する
- `thumbnail` がある場合は本文の前にアイキャッチとして表示する
- `description` は記事ヘッダーの概要文と SEO 用 description に使う
- `readingTime` は Phase 2 の方針に従い表示しない
- 関連記事は同じタグを持つ公開済み記事から最大 3 件を表示する
- 関連記事には現在表示中の記事を含めない

## 読了本詳細

読了本は一覧だけで終わらせず、Markdown 本文を読書メモとして表示します。

表示する情報:

- `title`
- `author`
- `publishDate`
- `publisher`
- `tags`
- Markdown 本文

表示方針:

- ページ上部に読了日、書名、著者、出版社、タグをまとめて表示する
- 表紙画像と評価は表示しない
- `publishDate` は読了日として表示する
- `publisher` と `tags` は値がある場合だけ表示する
- 本文は「読んだ理由」「よかった点」「メモ」など、Markdown 側の見出しをそのまま活用する
- `rating` は Phase 2 の方針に従い追加・表示しない
- 読了本同士の関連記事表示は Phase 4 では行わず、一覧へ戻る導線を置く

## Markdown 本文のデザイン

本文は Nuxt Content の `ContentRenderer` を使って描画します。

- `h2` / `h3` / `h4` の階層が視覚的に分かるようにする
- 段落、リスト、引用、区切り線の余白を統一する
- インラインコードとコードブロックを区別しやすくする
- コードブロックは横スクロールできるようにする
- リンクは本文色と区別し、キーボード操作時の focus 表示も維持する
- 画像は本文幅を超えないようにし、角丸と控えめな境界線を付ける
- 表は横幅が足りない場合に横スクロールできるようにする
- ライトモード / ダークモードの両方で文字とコードのコントラストを確保する
- Nuxt Content の見出し ID を使い、見出しへのアンカーリンクを利用できるようにする

スタイルは Nuxt UI と既存のデザイントークンを優先し、本文専用の調整は共通コンポーネントまたは `app/assets/css/main.css` にまとめます。

## データ取得

記事詳細:

- 現在の route path に一致する記事を `queryCollection('articles')` から 1 件取得する
- `published: true` の記事だけを表示対象にする
- データが存在しない場合は `createError({ statusCode: 404 })` で 404 にする
- 関連記事は公開済み記事を対象に、共通タグの有無で絞り込む
- 現在の記事を除外し、`publishDate` の降順で最大 3 件にする

読了本詳細:

- 現在の route path に一致する読了本を `queryCollection('books')` から 1 件取得する
- `published: true` の読了本だけを表示対象にする
- データが存在しない場合は 404 にする

補足:

- collection の `path` をリンク生成と詳細取得の共通キーとして使う
- query の組み立てはページ内に複雑な処理を残さず、必要に応じて composable に分ける
- `published: false` のコンテンツを URL の直接入力でも閲覧できないようにする

## SEO とメタ情報

Phase 6 でサイト全体の SEO、OGP、RSS、サイトマップを仕上げますが、詳細ページで必要になる基本メタ情報は Phase 4 で設定します。

- 記事は `title` と `description` を `useSeoMeta` に設定する
- 読了本はタイトル、著者、読書メモであることが分かる説明文を設定する
- 記事の`thumbnail`はOGP画像候補とし、読了本にはサイト共通OGP画像を使う
- canonical URL やサイト共通のタイトル形式は Phase 6 で統一する
- Markdown 本文内の最初の見出しより、ページタイトルを優先して文書構造を作る

## 実装ステップ

1. 記事詳細ページを作る
   - `app/pages/articles/[...slug].vue` を追加する
   - route path に一致する公開済み記事を取得する
   - 記事ヘッダーと `ContentRenderer` を配置する
   - 存在しない記事と非公開記事を 404 にする

2. 読了本詳細ページを作る
   - `app/pages/books/[...slug].vue` を追加する
   - route path に一致する公開済み読了本を取得する
   - 書籍情報とMarkdown本文を表示する
   - 存在しない読了本と非公開の読了本を 404 にする

3. Markdown 本文を整える
   - 見出し、段落、リスト、引用、リンク、画像、表を調整する
   - インラインコードとコードブロックの見た目を調整する
   - 長いコードと表が画面幅を超えないようにする

4. ページ内ナビゲーションを作る
   - Markdown の見出しから目次を表示する
   - 記事詳細に関連記事を最大 3 件表示する
   - 記事・読了本の一覧へ戻る導線を追加する

5. トップページからの遷移を有効にする
   - 記事カードを記事の `path` へリンクする
   - 読了本カードを読了本の `path` へリンクする
   - カード内のリンク構造とキーボード操作を確認する

6. メタ情報を設定する
   - 記事タイトルと description を設定する
   - 読了本タイトルと説明文を設定する
   - 記事サムネイルをOGP画像候補として扱えるようにする

7. レスポンシブ表示とテーマを仕上げる
   - PC では本文と目次を見やすく配置する
   - モバイルでは本文を 1 カラムにする
   - ライトモード / ダークモードで本文とコードを確認する

## テスト方針

- `vp exec pnpm build` でビルドが通ることを確認する
- サンプル記事の URL でタイトル、メタ情報、サムネイル、Markdown 本文が表示されることを確認する
- サンプル読了本のURLで書籍情報とMarkdown本文が表示されることを確認する
- トップページの記事カードから記事詳細へ遷移できることを確認する
- トップページの読了本カードから読了本詳細へ遷移できることを確認する
- 存在しない path が 404 になることを確認する
- `published: false` のコンテンツが URL の直接入力でも表示されないことを確認する
- `updated` / `publisher` / `tags` などの任意項目がなくても表示が崩れないことを確認する
- 関連記事に現在の記事と非公開記事が含まれないことを確認する
- Markdown の見出し、リスト、引用、リンク、画像、表、コードブロックが正しく表示されることを確認する
- 長いコードブロックと表がモバイル幅からはみ出さないことを確認する
- PC / タブレット / モバイルで本文幅、書籍情報、目次の表示が破綻しないことを確認する
- ライトモード / ダークモードで本文、リンク、コード、画像境界のコントラストを確認する

## 前提

- 詳細ページは Nuxt Content の page collection と `ContentRenderer` を使う
- 技術記事と読了本は、どちらも Phase 2 で定義した Markdown と frontmatter を利用する
- 読了本詳細ページを Phase 4 で実装し、Markdown 本文を読書メモとして表示する
- `readingTime` / `rating` / `category` は追加しない
- 記事の関連記事は既存の `tags` を使って判定する
- コメント、リアクション、SNS シェアボタンは Phase 4 の対象外にする
- 記事一覧ページ、読了本一覧ページ、タグ別ページ、年別アーカイブ、ページネーションは Phase 5 で扱う
- サイト全体の canonical URL、OGP 生成、RSS、サイトマップは Phase 6 で仕上げる
- 記事画像は`public/images/articles/`に置く
- Vite Plus 経由で検証する場合は `vp exec pnpm build` を使う

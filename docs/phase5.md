# フェーズ 5: ナビゲーションと発見性の実装計画

## 概要

技術記事と読了本を探しやすくするため、一覧ページ、タグ別ページ、年別アーカイブ、サイト内検索を整備します。
<br>トップページは新着コンテンツの入口として維持し、一覧ページでは公開済みコンテンツをまとめて閲覧できるようにします。

Phase 3 で用意したヘッダー、検索 UI、トップページのアーカイブ表示を土台にし、Phase 4 で作成した詳細ページへの導線をつなぎます。

ページネーションは記事数が少ない間も動作を確認できる構造にしますが、表示件数は定数として管理し、実データの増加に合わせて調整できるようにします。

## URL とファイル構成

```txt
app/
  pages/
    articles/
      index.vue
    books/
      index.vue
    tags/
      [tag].vue
    archives/
      [year].vue

  components/
    ArticleCard.vue
    BookCard.vue
    ContentPagination.vue
    ContentEmptyState.vue

  composables/
    useContentPagination.ts

  utils/
    content-navigation.ts
```

想定 URL:

- 記事一覧: `/articles`
- 読了本一覧: `/books`
- タグ別ページ: `/tags/Nuxt`
- 年別アーカイブ: `/archives/2026`

補足:

- タグ名は URL パラメータとして扱い、リンク生成時にエンコードする
- 年別アーカイブは技術記事を対象にする
- 一覧、タグ、アーカイブのページ番号は `?page=2` のクエリで表現する
- 存在しないタグ、年、ページ番号は空の一覧として残さず 404 として扱う
- 一覧からは Nuxt Content の `path` を使って詳細ページへ遷移する

## 記事一覧ページ

公開済みの技術記事を `publishDate` の降順で表示します。

表示する情報:

- `title`
- `description`
- `publishDate`
- `tags`
- `thumbnail`

表示方針:

- ページ上部にタイトル、説明、記事件数を表示する
- 記事カードはトップページと同じ情報設計にし、共通コンポーネントへ切り出す
- タグをクリックするとタグ別ページへ遷移する
- カード全体から記事詳細へ遷移できる構造と、タグリンクの操作を両立させる
- 記事が 1 ページの表示件数を超えた場合はページネーションを表示する
- ページを移動したときは一覧の先頭へ戻り、現在ページを見出しまたはページネーションで把握できるようにする

## 読了本一覧ページ

公開済みの読了本を `publishDate` の降順で表示します。

表示する情報:

- `title`
- `author`
- `publishDate`
- `publisher`
- `tags`
- `cover`

表示方針:

- `publishDate` は読了日として表示する
- 読了本カードはトップページと共通化する
- `publisher` と `tags` は値がある場合だけ表示する
- タグがある場合はタグ別ページへ遷移できるようにする
- 記事一覧とは独立したページネーションを持つ
- 表紙が小さくなりすぎないよう、PC とモバイルでカード配置を調整する

## タグ別ページ

記事と読了本の `tags` を横断し、指定したタグを持つ公開済みコンテンツを表示します。

表示方針:

- ページタイトルは「`{タグ名}` のコンテンツ」とする
- 技術記事と読了本をセクションで分ける
- 各セクションに該当件数を表示する
- 片方に該当データがない場合は、該当するセクションだけを表示する
- 両方に該当データがないタグは 404 にする
- タグ表記の大文字・小文字は登録済み frontmatter の表記を表示に使う
- 同じタグの表記揺れを自動統合する処理は入れず、コンテンツ側で統一する
- コンテンツ数が増えた場合にページネーションを追加できる取得構造にする

タグリンクは記事カード、読了本カード、詳細ページのタグ表示から同じ URL へ遷移させます。

## 年別アーカイブ

指定した年に公開された技術記事を `publishDate` の降順で表示します。

表示方針:

- ページタイトルは「`{年}年の記事`」とする
- `publishDate` の先頭 4 桁が URL の年と一致する公開済み記事を対象にする
- 年は 4 桁の数字だけを受け付ける
- 該当記事がない年は 404 にする
- トップページのアーカイブ件数と一覧結果が一致するよう、同じ集計ルールを使う
- 複数ページになる場合は `?page=` でページを切り替える
- 前後の年へのリンクは、実際に記事が存在する年だけ表示する

## サイト内検索

既存の `SiteSearch` と `UCommandPalette` を活用し、ヘッダーから記事と読了本を横断検索します。

検索対象:

- 技術記事: タイトル、説明、タグ
- 読了本: タイトル、著者、出版社、タグ

表示方針:

- 公開済みコンテンツだけを検索対象にする
- 検索結果を「記事」と「読了本」のグループに分ける
- 結果から選択すると詳細ページへ遷移し、モーダルを閉じる
- 結果がない場合は検索語を含む空状態を表示する
- 検索語が空の場合は、新しいコンテンツを候補として表示する
- `⌘K` / `Ctrl+K` で検索を開けるようにする
- ボタン、入力欄、検索結果をキーボードだけで操作できることを確認する

Phase 5 では frontmatter を対象にしたクライアント側検索とし、Markdown 本文の全文検索や外部検索サービスは導入しません。

## ページネーション

一覧のページ番号は URL の `page` クエリを唯一の状態として扱います。

- 1 ページあたりの表示件数を共通の定数で管理する
- `page` がない場合は 1 ページ目として扱う
- 0、負数、整数でない値、最終ページを超える値は 404 にする
- コンテンツが 1 件以上あれば、1 ページしかない場合も現在位置としてページネーションを表示する
- 前へ、次へ、ページ番号をキーボードで操作できるようにする
- ページ移動時もブラウザの戻る・進むが正しく動作するようにする
- 絞り込み条件を追加する場合も `page` と共存できる構造にする

初期実装では全件取得後にページ単位へ分割します。コンテンツ数が大きくなり、取得コストが問題になった場合は Nuxt Content の `skip` / `limit` を使う方式へ移行します。

## 共通 UI とナビゲーション

- `SiteHeader` の「記事」「読了本」を各一覧ページへつなぐ
- 現在の route に応じてメインナビゲーションの選択状態を表示する
- 詳細ページのパンくずリストから一覧ページへ戻れる状態を維持する
- 一覧、タグ別、年別ページにもホームへ戻れるパンくずリストを置く
- トップページの「全て見る」とアーカイブリンクを有効なページへつなぐ
- 空状態、読み込み状態、ページネーションの見た目を一覧間で統一する
- ライトモード / ダークモードの semantic color を使い、色を直接固定しない
- PC ではカードを複数列、モバイルでは 1 カラムで表示する

## データ取得

記事一覧:

- `queryCollection('articles')` から `published: true` の記事を取得する
- `publishDate` の降順で並べる
- 現在ページに必要な範囲を表示する

読了本一覧:

- `queryCollection('books')` から `published: true` の読了本を取得する
- `publishDate` の降順で並べる
- 現在ページに必要な範囲を表示する

タグ別ページ:

- 記事と読了本を並列に取得する
- `tags` に指定タグを含む公開済みコンテンツだけを残す
- URL の値はデコードしたうえで登録済みタグと照合する

年別アーカイブ:

- 公開済み記事を取得し、`publishDate` の年で絞り込む
- 利用可能な年と件数の集計処理をトップページと共通化する

補足:

- 非公開コンテンツを件数、検索結果、ページ数に含めない
- 一覧取得と派生データの処理は composable または utility にまとめる
- `useAsyncData` のキーにはページ種別、タグ、年、ページ番号を含め、別ページのデータが混ざらないようにする

## SEO とメタ情報

サイト全体の canonical URL、OGP、RSS、サイトマップは Phase 6 で仕上げますが、各ページ固有の基本メタ情報は Phase 5 で設定します。

- 記事一覧と読了本一覧に固有の `title` と `description` を設定する
- タグ別ページはタグ名をタイトルと説明文に含める
- 年別アーカイブは対象年をタイトルと説明文に含める
- 2 ページ目以降はページ番号をタイトルに含める
- 存在しない条件を 404 にし、内容のないページを検索対象にしない

## 実装ステップ

1. 共通の一覧 UI を整理する
   - 記事カードと読了本カードを共通コンポーネントへ切り出す
   - トップページと一覧ページから利用できる props に整える
   - タグリンクとカード全体のリンク構造を調整する

2. 記事一覧と読了本一覧を作る
   - `/articles` と `/books` を追加する
   - 公開済みコンテンツを日付の降順で表示する
   - 件数、空状態、基本メタ情報を設定する

3. ページネーションを作る
   - `page` クエリの検証と表示範囲の計算を共通化する
   - 一覧ページにページネーションを追加する
   - 不正なページ番号と範囲外ページを 404 にする

4. タグ別ページを作る
   - `/tags/[tag]` を追加する
   - 記事と読了本をタグで絞り込む
   - カードと詳細ページのタグをタグ別ページへつなぐ

5. 年別アーカイブを作る
   - `/archives/[year]` を追加する
   - 公開年で記事を絞り込む
   - トップページの年別件数と集計処理を共通化する

6. 検索 UI を仕上げる
   - 検索対象と非公開コンテンツの除外を確認する
   - 検索結果なしの表示を追加する
   - macOS と Windows のショートカット、キーボード操作を確認する

7. ナビゲーションとレスポンシブ表示を仕上げる
   - ヘッダーの現在地表示を route に連動させる
   - パンくずリストと前後の導線を確認する
   - PC / モバイルとライト / ダークモードを確認する

## テスト方針

- `vp exec pnpm build` でビルドが通ることを確認する
- `/articles` に公開済み記事だけが日付の降順で表示されることを確認する
- `/books` に公開済み読了本だけが読了日の降順で表示されることを確認する
- 記事カードと読了本カードから詳細ページへ遷移できることを確認する
- タグリンクから、同じタグを持つ記事と読了本を確認できることを確認する
- URL エンコードが必要な日本語や記号を含むタグで遷移できることを確認する
- 存在しないタグが 404 になることを確認する
- 年別アーカイブの件数と表示記事がトップページの集計と一致することを確認する
- 4 桁でない年と記事が存在しない年が 404 になることを確認する
- ページネーションの最初、途中、最後のページで表示件数とリンクを確認する
- 不正な `page` と最終ページを超える `page` が 404 になることを確認する
- 検索で記事のタイトル、説明、タグを検索できることを確認する
- 検索で読了本のタイトル、著者、出版社、タグを検索できることを確認する
- 非公開コンテンツが一覧、タグ、アーカイブ、検索、件数に含まれないことを確認する
- マウスを使わずにナビゲーション、検索、ページネーションを操作できることを確認する
- PC / タブレット / モバイルでカード、パンくず、ページネーションが崩れないことを確認する
- ライトモード / ダークモードで選択状態、リンク、カードのコントラストを確認する

## 前提

- 技術記事と読了本は Phase 2 で定義した Nuxt Content collection を使う
- 詳細ページと Markdown 本文は Phase 4 の実装を利用する
- `published: false` のコンテンツはすべての発見導線から除外する
- 年別アーカイブは技術記事だけを対象にする
- タグ別ページは技術記事と読了本を横断する
- 検索は既存の `SiteSearch` と Nuxt UI の `UCommandPalette` を使う
- Phase 5 では Markdown 本文の全文検索と外部検索サービスを導入しない
- タグ一覧専用ページ、複数タグの AND / OR 絞り込み、並び替え UI は対象外にする
- canonical URL、OGP 生成、RSS、サイトマップ、専用 404 ページは Phase 6 で仕上げる
- Vite Plus 経由で検証する場合は `vp exec pnpm build` を使う

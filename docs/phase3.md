# フェーズ 3: 添付デザイン準拠のトップページ計画

## 概要

トップページは、添付デザインを基準に「最新記事一覧が主役の白基調カードグリッド + 右サイドバー」として作ります。
<br>大きなヒーローや説明カードは置かず、ファーストビューから最新記事、プロフィール、サイト説明、アーカイブが見える構成にします。

ヘッダーには生成済みの `Yuri's Blog` ロゴ画像を使います。横長ロゴをそのまま使うか、アイコン部分だけを切り出してサイト名テキストと組み合わせるかは実装時に表示バランスで決めます。

Phase 2 のコンテンツ設計を優先し、記事の `readingTime`、読了本の `rating`、分類用の `category` は Phase 3 では追加しません。

## 画面構成

```txt
app/pages/index.vue

トップページ
  ヘッダー
    Yuri's Blog ロゴ
    ナビゲーション
    検索ボタン
    テーマ切替

  メインカラム
    最新記事一覧
      記事カードグリッド
      全ての記事を見る導線

    読了本一覧
      横長カード
      全ての読了本を見る導線

  右サイドバー
    プロフィール
    このサイトについて
    アーカイブ

  フッター
```

- PC はメインカラム + 右サイドバーの 2 カラムにする
- 記事一覧は PC で 3 列、タブレットで 2 列、モバイルで 1 列にする
- モバイルでは右サイドバーを本文下に回す
- トップページでは最新記事と最新の読了本を抜粋表示し、全件表示は一覧ページへの導線で扱う
- UI は Nuxt UI のコンポーネントを優先して使う
- CSS は `app/assets/css/main.css` の既存トークンを活かし、必要な調整だけに留める

## デザイン方針

- 背景は白基調にし、カードの境界線と薄い影で情報を区切る
- ヘッダー左には `Yuri's Blog` ロゴ画像を配置し、背景になじむように高さと余白を調整する
- セクション見出しには添付デザインのような左側の縦アクセントを入れる
- 記事セクションの見出しは `最新記事一覧` にし、右側に `全ての記事を見る` ボタンを置く
- 読了本セクションの見出しは `最新の読了本` にし、右側に `全ての読了本を見る` ボタンを置く
- 記事カードはサムネイルを大きく見せ、下部にタグ、タイトル、公開日を配置する
- トップページの高さを抑えるため、記事カードには `description` を表示しない
- 読了本カードは表紙画像を左、書籍情報を右に置く横長カードにする
- サイドバーのプロフィールは中央寄せにし、アバター、名前、肩書き、説明、SNS アイコン導線を配置する
- ダークモードでも背景、カード、文字色、タグ、アイコンのコントラストが崩れないようにする

## データ取得

トップページでは `queryCollection('articles')` と `queryCollection('books')` を使います。

記事:

- `published: true` の記事だけを表示する
- `publishDate` の降順を初期表示にする
- トップページでは最新 6 件を表示する
- 一覧では `title` / `publishDate` / `tags` / `thumbnail` を使う
- `description` は詳細ページや記事一覧ページで使い、トップページのカードには表示しない
- `readingTime` は使わない

読了本:

- `published: true` の読了本だけを表示する
- `publishDate` の降順を初期表示にする
- トップページでは最新 3 件を表示する
- 一覧では `title` / `author` / `publishDate` / `cover` / `publisher` / `tags` を使う
- `rating` は使わない

補足:

- `published: false` はトップページに出さない
- 記事分類は `category` ではなく `tags` を主軸にする
- タグ一覧と年別アーカイブは記事データから集計する
- タグフィルターと並び替え UI はトップページには置かず、記事一覧ページや読了本一覧ページで扱う
- トップページにはページネーションを置かず、`全ての記事を見る` / `全ての読了本を見る` の導線を置く
- 一覧ページとページネーション本実装は Phase 5 で扱う

## 実装ステップ

1. ヘッダーを作る
   - 左に `Yuri's Blog` ロゴ画像を配置する
   - ロゴ画像は `public/images/logo.png` など、公開配信しやすい場所に置く
   - 横長ロゴが大きすぎる場合は、アイコン部分を切り出してサイト名テキストと組み合わせる
   - 中央に `ホーム` / `記事` / `読了本` / `アバウト` / `お問い合わせ` を配置する
   - 右に検索ボタンとテーマ切替ボタンを配置する
   - 現在位置を示す active underline を入れる

2. メインレイアウトを作る
   - PC では記事一覧 + 右サイドバーの 2 カラムにする
   - モバイルでは 1 カラムにする
   - 添付デザインに合わせて大きなヒーローは置かない

3. 最新記事一覧を作る
   - 見出し `最新記事一覧` と説明文を表示する
   - 右側に `全ての記事を見る` ボタンを表示する
   - 最新記事カードを最大 6 件までレスポンシブグリッドで表示する
   - 記事カードには `description` を出さず、カード高さを抑える
   - サムネイルがない場合の fallback を用意する

4. 読了本一覧を作る
   - 見出し `最新の読了本` と説明文を表示する
   - 右側に `全ての読了本を見る` ボタンを表示する
   - 最新の読了本を最大 3 件まで横長カードで表示する
   - 表紙、タイトル、著者、読了日、出版社、タグを表示する
   - 評価は表示しない

5. 右サイドバーを作る
   - `プロフィール` カードを作る
   - `このサイトについて` カードを作る
   - `アーカイブ` カードを作る
   - タグフィルターや並び替え UI は一覧画面側に置くため、右サイドバーには置かない

6. フッターを作る
   - コピーライトを表示する
   - `プライバシーポリシー` / `お問い合わせ` / `サイトマップ` の導線を置く

7. 仕上げる
   - `全ての記事を見る` / `全ての読了本を見る` 導線の見た目を確認する
   - ライトモード / ダークモードの見え方を確認する
   - PC / タブレット / モバイルでカード列数と余白を確認する

## テスト方針

- `vp exec pnpm build` でビルドが通ることを確認する
- `queryCollection('articles')` / `queryCollection('books')` が型付きで利用できることを確認する
- `published: true` の記事・読了本だけが表示されることを確認する
- `published: false` の記事・読了本が一覧に出ないことを確認する
- 記事一覧が初期状態で `publishDate` の降順になることを確認する
- トップページの記事表示が最大 6 件になることを確認する
- トップページの読了本表示が最大 3 件になることを確認する
- `全ての記事を見る` / `全ての読了本を見る` の導線が表示されることを確認する
- PC 幅で記事 3 列 + 右サイドバーになることを確認する
- タブレット幅で記事 2 列になることを確認する
- モバイル幅で記事 1 列になり、右サイドバーが本文下に回ることを確認する
- ライトモード / ダークモードで背景、文字色、カード境界、タグ、アイコンが破綻しないことを確認する

## 前提

- トップページは `app/pages/index.vue` に実装する
- `docs/phase3.md` は既存内容を部分修正ではなく、添付デザイン準拠の内容に差し替える
- ロゴ画像は生成済み画像を利用するが、実装時に必要であれば余白除去やアイコン切り出しを行う
- Phase 2 の方針を優先し、`readingTime` / `rating` / `category` は追加しない
- 検索本実装は Phase 5 で扱う
- 記事詳細ページと読了本詳細ページは Phase 4 で扱う
- 記事一覧ページ、読了本一覧ページ、タグフィルター、並び替え UI、タグ別ページ、年別アーカイブページ、ページネーション本実装は Phase 5 で扱う
- 画像は `public/images/articles/` と `public/images/books/` に置く
- サムネイルや表紙画像の拡張子は `.jpg` / `.png` / `.webp` を基本にする
- Vite Plus 経由で検証する場合は、Node.js のバージョン差を避けるため `vp exec pnpm build` を使う
